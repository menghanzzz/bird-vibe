# 第一部分：系统架构与功能

## 1.1 系统定位

BirdVibe 是面向观鸟入门者的 AI 应用：上传照片识别鸟种 → 解锁图鉴 → 记录足迹地图 → 社区分享。整个系统由**前端（Next.js）+ 后端（FastAPI）+ Markdown 知识库**三部分组成，前后端分离、HTTP 对接。

```
┌─────────────────────────────────────────────────────────────┐
│ 前端 bird-vibe-app/（Next.js 16.2.7 + React 19，端口 3000）   │
│ / 数据看板 · /recognize 识别 · /pokedex 图鉴 · /map 地图 ·   │
│ /community 社区                                             │
└──────────────┬──────────────────────────────────────────────┘
               │ HTTP（API_BASE_URL，默认 localhost:8000）
┌──────────────▼──────────────────────────────────────────────┐
│ 后端 backend/（FastAPI + Python 3.12 venv，端口 8000）        │
│ main.py ──┬── rag_service.py      知识库检索/解析/自动入库    │
│ （4 路由） ├── bioclip_service.py  BioCLIP 一级识别+千问兜底  │
│           └── scripts/batch_eval.py  批量 A/B 评估           │
└──────────────┬──────────────────────────────────────────────┘
┌──────────────▼──────────────────────────────────────────────┐
│ 数据层                                                      │
│ knowledge_base/  42 个鸟类 .md（YAML frontmatter + 4 章节）   │
│ training_data/   48 物种 ~2800 张微调备图 + manifest.json     │
│ eval_set/        348 张评测集 + 三轮原始数据 + 本报告          │
└─────────────────────────────────────────────────────────────┘
```

## 1.2 后端 API（4 个路由）

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/api/v1/birds` | 全部鸟种轻量元数据（图鉴卡片） |
| GET | `/api/v1/birds/{name}/details` | 单鸟四章节详情（外貌/习性/鸣叫/分布） |
| POST | `/api/v1/birds/search` | 关键词计数式语义搜索 top5（纯文件系统，无向量库） |
| POST | `/api/v1/recognize` | 照片识别主链路（下详） |

## 1.3 识别主链路（被测核心）

```
用户照片
  │
  ├─ recognizer=bioclip ──► BioCLIP（本地 CLIP，imageomics/bioclip ViT-B/16）
  │                          图片 vs 知识库全部鸟种"拉丁学名+中文名"双标签
  │                          相似度 softmax 排序，取每鸟最高分
  │                          top1 ≥ 0.40 → 直接返回 BioCLIP 结果
  │                          top1 < 0.40 或模型不可用 → 回退千问，标 qwen_fallback
  │
  └─ 默认（standard/free）──► qwen3-vl-plus（阿里云百炼视觉大模型）
                               standard：自由识别 prompt + 地点/日期软提示
                                         + 代码层知识库后验匹配（find_kb_match）
                               free：极简 prompt（回归对照）
                               识别结果：top5 候选（名/置信度/依据）+ 消歧追问卡片
                               │
                               ▼
                         top1 不在知识库 → 自动入库管线：
                         qwen-flash 生成资料 → 格式校验（拉丁名双名法，重试≤3）
                         → iNaturalist API 双维校验 → 写入 knowledge_base/{鸟名}.md
```

**关键设计**：混合架构（本地专用模型 + 云端大模型兜底）、置信度阈值回退、别名归一化（"白鹭"匹配"小白鹭"）、开放集新鸟自动入库。BioCLIP 分数是 **84 个标签上的 softmax 概率**（不是原始余弦相似度），这直接决定了阈值语义。

## 1.4 前端五个页面

## 1.5 技术栈要点

- **前端**：Next.js 16 App Router、React 19、Tailwind v4、shadcn、zustand v5 persist、echarts/leaflet/canvas-confetti
- **后端**：FastAPI 0.141、dashscope 1.27（`qwen3-vl-plus` 视觉识别、`qwen-flash` 文本生成）、torch 2.2.2 + open_clip_torch 3.3（Intel Mac 受 torch x86 wheel 约束）、openpyxl/requests/PyYAML
- **模型**：BioCLIP（HF imageomics/bioclip，本地 CPU）、qwen3-vl-plus（百炼 API）、qwen-flash（入库资料生成）
- **评测基建**：`scripts/batch_eval.py`（批量 A/B 评估，自动起隔离后端、防知识库污染）、`scripts/build_eval_set.py`（测试集构建，含泄漏检查硬门槛）

# 第二部分：测试计划

## 2.1 测试目的（为什么要测）

本项目评测不止于"报一个准确率"，它有四个层层递进的目的：

1. **模型替换验收**：原识别模型 `qwen-omni-turbo` 被百炼官方批量下线（2026-10-10），需要数据证明替换后的 `qwen3-vl-plus` 至少不差、最好更好；
2. **架构决策**：混合管道里"本地 BioCLIP vs 云端 qwen"谁该当主力？阈值 0.20 合理吗？地理软提示有用吗？——每个设计决策都要有证据；
3. **质量底线**：幻觉率（编造不存在的鸟种）、OOD 行为（非鸟图怎么办）、拒答输出会不会污染数据——这些是上线红线；
4. **闭环示范**：完整走通"评测发现 → 假设 → 改进 → 复评验证"的工程循环（本项目同时也是面试者的能力证明）。

## 2.2 测试对象（测什么）

被测对象是一个**复合 AI 系统**，不是单个模型。这是现代 AI 评测岗位的核心认知，拆解如下：

| 层 | 组件 | 被测问题 |
|---|---|---|
| L1 感知层 | BioCLIP（预训练） | 闭集分类能力、置信度质量（校准）、阈值行为 |
| L2 认知层 | qwen3-vl-plus（standard/free 两种 prompt） | 开放世界识别、幻觉、指令遵循、prompt 设计 |
| 链路层 | 阈值回退、别名归一、消歧追问 | 工程策略是否合理 |
| 数据层 | 自动入库管线（qwen-flash + 校验 + iNat） | 生成质量、校验通过率、污染防护 |
| 配套层 | RAG 检索、知识库完整性 | 数据闭环质量 |

**任务形式化**：细粒度视觉分类（FGVC），48 类候选，系统输出 top5 候选（名称+置信度+识别依据），产品消费 top3（识别页展示 top3 卡片）。这个定义决定了所有指标口径——top3 是用户体验口径，top1 是模型口径，两者都报。

## 2.3 测试集构建（方法学与执行）

### 2.3.1 规模论证：n 由三个约束的交集决定

| 要支持的结论 | 统计要求 | 对 n 的约束 |
|---|---|---|
| qwen vs BioCLIP（预期差 16pp） | McNemar 需 ~20 个不一致对（不一致率 ~30% 时） | n ≈ 70–100 |
| bioclip 相关小差距检验 | 不一致对更多才够 | n ≈ 250–350 |
| 整体准确率 95% CI 半宽 ≤ ±5pp | n=300 时 ±4.6pp，n=384 时 ±4.2pp | n ≥ 300 |
| ECE 校准（10 桶可靠性图） | 每桶 ≥30 个点 | n ≥ 300 |
| 混淆矩阵 / per-class | 每类 ≥5–8 张才有方向性意义 | 48 类 × 6–8 = 288–384 |

**结论：核心集 48 类 × 7 张 = 336 张**，加野外层 12 张，合计 348 张。

### 2.3.2 三层测试集设计

| 层 | 来源 | 数量 | 目的 |
|---|---|---|---|
| core（核心层） | training_data 的 val/ 子集分层抽样（iNat 科研级照片） | 336 | 主体指标；同种多姿态，比实拍更难 |
| wild（野外层） | 用户实拍 12 张（现有资产） | 12 | 分布外表现：训练数据是精选图，用户上传是随手拍 |
| OOD（分布外层） | 合成非鸟图（噪点/纯色/几何/鸟形剪影） | 12 | 拒绝行为；局限：合成 ≠ 真实猫/车照片，结论外推需谨慎 |

### 2.3.3 泄漏检查硬门槛（微调对比的生命线）

测试集与训练集重叠会让准确率虚高。`build_eval_set.py` 设三道门槛，**任一违规整体拒绝构建**：

1. **observation_id 级**：manifest.json 记录每张图的 iNat observation_id；选中图的 id 不得出现在同物种 train/ 中；
2. **文件名级兜底**：val 文件名（即 observation_id）不得与 train/ 文件名重叠；
3. **全局 sha256 去重**：跨物种完全重复文件视为数据缺陷，硬失败。

执行结果：**0 违规**（seed=42，可复现）。审计记录：`eval_set/build_manifest.json`。

### 2.3.4 金标规范与命名约定

- 金标 = 物种目录名（物种级中文名），**禁止统称**（"白鹭""猫头鹰"不合格——评测初期 11.jpg 金标"白鹭"被修正为"小白鹭"，这正是规范的价值）；
- 别名处理是**评测工程决策**而非数据补丁：模型答"喜鹊"而金标是"普通喜鹊"（iNat 命名风格），需要证据驱动的别名表（≥数张证据才准入），属级通名（银鸥→蒙古银鸥）**刻意不收**——模型没到物种级就该记未命中，不能靠别名表灌水。

## 2.4 指标体系（构建逻辑：每个指标为什么存在）

### A. 正确性指标

| 指标 | 计算 | 为什么选它 |
|---|---|---|
| Top-1 / Top-3 命中率 | 命中数/n | top3 是产品真实消费形态（识别页展示 top3 卡片），top1 是模型口径；两个都报 |
| 归一化命中率 | find_kb_match 判等价（"白鹭"="小白鹭"） | 判"对人是否有用"而非字符串相等；同时检验归一逻辑本身 |
| Macro-F1 / macro top3 | 每类先算再平均 | 48 类稀有度极不均衡（极度常见 vs 稀有），micro/accuracy 会被常见种主导；macro 才能暴露稀有类崩盘 |
| 混淆矩阵 + 易混淆对 | per-class 准确率、错答聚合 | 直接验收 CONFUSABLE_GROUPS 设计、喂给消歧功能 |

### B. 置信度质量（校准）指标

BioCLIP 的输出是 softmax 概率，阈值直接决定回退行为——"0.20 是拍的还是算的"必须用数据回答：

- **ECE（期望校准误差）**：预测按置信度分 10 桶，ECE = Σ(|Bₘ|/n)·|acc(Bₘ) − conf(Bₘ)|。衡量"分数 0.8 的预测是不是真的约 80% 对"；
- **可靠性图**：ECE 的可视化；
- **Risk-Coverage 曲线**：扫描阈值 t∈[0.05,0.99]，每点得（覆盖率，接受集错误率）；并把"被拒样本交给千问兜底"纳入，得到**混合系统 top1 曲线**。这是唯一能回答"阈值该定多少"的工具；
- 配套回退指标：**回退率**（兜底触发占比）、**回退精确率**（回退样本中千问救回比例）、**端到端命中率**。

### C. 生成质量与幻觉指标

| 指标 | 裁判 | 为什么 |
|---|---|---|
| 幻觉率 | 候选鸟名查知识库 + iNaturalist taxa API | 编造不存在的鸟种是最坏失败模式；复用系统已有的权威校验管线做裁判 |
| 拉丁名合法率 | 双名法正则 | 轻量幻觉探针 |
| JSON 格式合规率 | 解析失败率 | 指令遵循基础线 |
| reason 解释质量 | 人工小样本 1–5 分 + 形态词代理指标 | 可解释性是产品卖点，需要人的判断 |

### D. 鲁棒性与 OOD 指标

- **条件分桶准确率**：鸟体占比/光照/遮挡/背景/单只 vs 群鸟分桶 → 找短板桶；
- **退化曲线**：同图 PIL 三级模糊/降分辨率/压暗 → 最低可接受画质；
- **OOD 错误自信率**：非鸟图中系统仍自信给出具体物种的比例；理想行为是低置信或拒答。

### E. 效率与成本指标

- 延迟 P50/P95（分 BioCLIP 本地 / qwen API / 端到端；用 P95 因为用户体验由尾部决定）；
- tokens/张、元/张、免费额度可支撑次数——**先试点标定单位成本，再决定全量规模**（实测 0.0077 元/次调用，输出 token 占成本 ~90%）。

### F. 统计严谨性（让结果"可信"的最后一公里）

- **McNemar 检验**：同一测试集上两个模型的逐样本配对比较（b/c 表），小样本下比 t 检验更合适，是模型对比的标准做法；
- **Bootstrap 置信区间**：对准确率差做 10000 次重采样，报 95% CI；
- **n 的诚实声明**：每类仅 7 张时单类 CI 仍有 ±35pp 量级——per-class 数字只看方向，报告写清。

### G. 冷/暖库双口径（评测中提炼的原则）

系统带自动入库，KB 会增长，因此同一系统存在两个合法口径：

- **冷库（封闭集）**：KB 冻结在 42 物种 → 测 BioCLIP 闭集能力 + 阈值行为；非 KB 类的 52 张照片结构性不可命中；
- **暖库（系统级）**：预载全部评测物种（42+7=49）后冻结 → 测"含入库能力的稳态系统"真实水平；
- **严禁第三种状态**：评测期间让 KB 自由增长——分数会漂移、后半程还会"开卷考试"（详见第四部分事故记录）。

## 2.5 测试方法的选择理由（汇总）

| 选择 | 理由 |
|---|---|
| 配对设计（同图过两个系统） | 消除图片难度差异，McNemar/bootstrap 都建立在配对之上；比"两个独立准确率相减"严谨一个量级 |
| 离线重打分 | BioCLIP 本地可跑：改标签集/改阈值后重算只需 CPU 时间，零 API 成本（暖库口径就是这么补齐的） |
| 合成 OOD | 真实非鸟照片无现成来源；合成图覆盖"明显非鸟"和"鸟形剪影"两档，局限明示 |
| 试点先行（48 张） | 先实测 token 单价（0.0077 元/调用）再承诺全量，避免预算失控 |
| 隔离后端 + 冻结开关 | 评测绝不能污染真实知识库；冻结消除评测期 KB 增长的方法学噪声 |
| 增量补洞（--only） | API 欠费/中断后只重跑受损照片，不浪费已花掉的调用费（本次使用 2 次） |

## 3.0 起因：模型批量下线（2026-10-10）

阿里云百炼官方公告对老模型批量下线，`qwen-omni-turbo` 全系列在列，识别功能当日瘫痪。调研结论：百炼无永久免费视觉模型，"免费"= 每模型 100 万 Token/90 天；当前在列的专业视觉模型只有 `qwen3-vl-plus`（千问VL 区唯一），omni 系官方推荐替换（qwen3.5-omni-plus）图片输入贵 50 倍且音频能力用不上。代码两处替换（`main.py` 视觉、`rag_service.py` 文本生成 `qwen-turbo`→`qwen-flash`——后者也已从计费页消失，不换迟早再炸），真实调用冒烟通过后服务恢复。12 张野外集旧模型 top1 = 58.3%，成为"模型替换验收"的对照。

## 3.1 Phase 0：环境冻结与基线

- **冻结四要素**（`eval_snapshots/manifest_2026-10-14.json`）：git HEAD + 4 个识别相关文件 sha256（工作区有未提交改动）、42 个知识库文件快照 tar + 逐文件哈希、测试集 Excel+照片逐张哈希、BioCLIP HF 权重 revision+文件哈希、venv 关键包版本；

- **12 张基线**（qwen3-vl-plus）：std top1 83.3%、bioclip 66.7%——与旧模型同集对比 +25pp。

### 事件 ①：首次基线中途崩溃 + 账户欠费（同日）

跑到 9/12 时两张照片四轮重试全失败，且重试耗尽后**整个脚本崩溃**（`run_one_round` 失败路径返回 3 元组、调用方解包 4 个值的 bug——此前从未被触发过，因为只有"重试耗尽"才走这条路径）。修复后定位根因：阿里云 **Access denied / account not in good standing**，用成功过的图片 + 文本模型交叉验证确认为**账户级欠费**（与图片、模型无关）。用户充值后全量重跑成功。
**教训**：①评测工具自身的失败路径也要被测到；②账户级故障的重试是无用功，应快速失败。

## 3.4 四项深度分析（本地免费 + 0.1 元 OOD）

1. **Risk-coverage + ECE**：离线扫描预测混合系统在阈值 0.40 最优（+0.6pp），ECE 0.136 全区间过自信；
2. **别名裁判升级**：括号注释剥离（"黄鹡鸰（幼鸟）"）+ 证据驱动别名表；属级通名刻意不收；
3. **OOD 测试**：qwen 10/12 干净拒答、2/2 鸟形剪影幻觉；BioCLIP 11/12 自信幻觉（噪点图都敢答黄鹡鸰 0.76），其中 8 次置信 <0.40 → **0.40 阈值被独立验证**（能拦 8/11）；残差 4 张 0.67~0.77 高自信幻觉为阈值法固有局限；
4. **正式假设检验**：BioCLIP>std p=8.5e-06；free>std p=0.08（不显著，如实报告）。

## 3.5 行动清单执行与 v2 复评

**变更①**：阈值 0.20→0.40（代码 + AGENTS.md + 单元验证：边界样本正确翻转）。
**变更②**：std prompt v2（反锚定措辞"不要因为地点倾向当地常见种"，日期保留）。

### v2 结果（348×3，欠费中断 13 张已补洞）

- prompt v2：std top3 75.0→77.0，McNemar **9:2，p=0.070**——看似有效；
- 阈值 0.40：回退 1→13 次（机制生效），但 bioclip 轮 top1 74.4→71.8（p=0.052）——**与离线预测（+0.6pp）符号相反**。

### 事件 ④：第二次欠费 + 补洞机制验证

欠费窗口损坏 13 张（c296~c308），充值后 `--only` 增量补洞（~0.3 元）恢复 0 error。补洞期间还捕获到 c301 bioclip 轮 error = **0.40 阈值真实触发后回退千问撞上欠费**——阈值机制的工作证据。

### 事件 ⑤：评测抓出高危产品 bug

v2 期间发现 qwen 把拒答输出（"无法识别""图像中无可见鸟类"）填进 name 字段，被当作新物种**成功入库 4 次**——真实用户上传废图就会污染图鉴。根因：入库门槛无拒答过滤（且 LLM 生成器会顺着荒谬输入编出"合规"拉丁名骗过格式校验）。修复：黑名单+否定前缀双重拦截。

### 事件 ⑥：KB-drift——被污染的对照

v1/v2 评测期间自动入库把隔离 KB 从 42 物种养到 ~80（38 个新物种），越晚评测的照片 softmax 分母越大、分数系统性下移。后果双重：①阈值对照失效（13 张 v1 时 >0.40 的样本 v2 时被误拒）；②**开卷考试**——系统把 7 个评测物种现学现卖，后半程 BioCLIP 对它们直接命中（v1 的 86.5% 里含此水分）。
对策三连：`BIRD_DISABLE_INGEST=1` 冻结开关、batch_eval 默认冻结、服务器日志改时间戳轮转（固定文件名曾导致入库失败归因证据被下一次运行覆盖丢失——教训：**评测证据必须版本化**）。

## 3.6 v3 冻结重跑（最终干净测量，348×3，入库 0 次/冻结拦截 276 次）

| 指标 | v1（污染） | v2（污染） | **v3 冷库** | v3 暖库（离线扩展标签） |
|---|---|---|---|---|
| std top1/top3 | 62.1/75.0 | 61.5/77.0 | 60.9/75.6 | — |
| free top1/top3 | 62.9/77.3 | 63.8/77.9 | 63.5/77.9 | — |
| bioclip轮 top1/top3 | 74.4/86.5 | 71.8/85.6 | **71.3/79.9** | **78.2/90.5** |

**终版判定**：
1. **prompt v2 无显著效果**（v3 vs v1：9:7，p=0.80）——v2 时的"提升"是漂移噪声。保留措辞（方向合理、无害）但不宣称收益；
2. **阈值 0.40 准确性收益 = 0**（冻结数据上 0.20/0.30/0.40 混合 top1 同为 71.3%）——保留理由只剩 OOD 安全；
3. **v1 的 86.5% 之谜破解**：暖库才是系统稳态真实水平（top3 90.5%），v1 是"半开卷"；
4. **最终架构结论**：暖库 BioCLIP top1 78.2% / top3 90.5%，对 qwen-std 70:34（p=6e-04）；**qwen 的正确定位 = 低分兜底 + OOD 拒答，不承担主识别**。BioCLIP 对 qwen 的优势在冷库口径收窄但方向与显著性不变。
5. 暖库口径零成本实现：本地 BioCLIP + 扩展 7 物种标签（拉丁名取自 manifest）对 52 张非 KB 类照片离线重打分。

# 第五部分：方法学总结（面试速查）

**一句话故事**："348 张泄漏检查测试集、三轮迭代、~17 元预算，最终确立本地专用模型显著优于云端大模型（top1 78.2% vs 60.9%）；过程中证伪了自己的两个改进假设、发现被测系统在开卷考试、修复三个真实 bug——评测驱动了架构决策。"

1. **测试集构成决定结论**：12 张野外集（常见菜鸟）说 qwen 赢，348 张核心集（细粒度区分）说 BioCLIP 赢——两者都对，只是测了不同分布；报结论必须带测试集画像；
2. **被测系统会自己进化**（自动入库）：要么冻结（冷口径），要么预载后冻结（暖口径），绝不允许评测中自由生长；
3. **离线预测 ≠ 在线复现**：risk-curve 预测 +0.6pp、实测 -2.6pp，根因是环境漂移——涉及"分数"的指标必须验证测量环境的一致性；
4. **评测裁判与被测系统的语义要对齐**：命名约定、别名、括号注释、统称——27/348（7.8%）的"错误"其实是语言问题；
5. **配对 + McNemar + bootstrap CI** 是小样本模型对比的标准动作；方向性结果（p=0.08）如实报告为"暗示"而非"结论"；
6. **失败路径是隐藏测试盲区**：3 元组 bug、欠费重试、拒答入库，全都在异常路径里；
7. **先试点标定单位成本**（0.0077 元/调用）再承诺全量；**增量补洞**（--only）让中断的损失最小化；
8. 评测的副产品往往最值钱：拒答入库是高危生产 bug， drift 是方法学洞见——**评测工程师的价值在"发现"，不在"打分"**。
